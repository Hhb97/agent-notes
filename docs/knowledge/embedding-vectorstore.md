# embedding 与向量库

> [!ABSTRACT] 一句话版本
> - **embedding 把文本映射成一组数字**，语义相近的文本在向量空间里距离也近；它用于「找相似」，不是「压缩原文」。
> - 向量库的职责是**存向量 + 高效找最近邻 + 按元数据过滤**；大规模时用 ANN 索引（如 HNSW）换速度，代价是近似而非精确。
> - **维度必须与 embedding 模型一致**，换模型要全量重建；不同模型的向量不能混在同一索引里比较。
> - 选型看四件事：数据规模、过滤能力、混合检索支持、运维与持久化，而不是只看 benchmark 数字。

| 概念 | 说明 |
| --- | --- |
| **向量维度** | 模型输出的固定长度（常见几百到几千维），配置必须与模型一致 |
| **余弦相似度** | 比较方向，常用于文本语义；归一化后与点积等价 |
| **欧氏距离 / 点积** | 其他常见度量，需与索引配置、模型训练目标匹配 |
| **归一化** | 把向量长度统一，避免文本长度影响相似度 |
| **ANN 索引** | HNSW / IVF 一类近似最近邻结构，用少量召回损失换大规模检索速度 |

> [!NOTE] embedding 不保存原文
> 向量是「语义坐标」，不能还原出原文。索引里必须同时保存 chunk 文本与元数据，才能把命中结果拼进提示词并展示引用。

## 二、向量库要提供什么

| 能力 | 为什么需要 |
| --- | --- |
| 相似度检索 Top-K | 基础能力 |
| **元数据过滤** | 权限、部门、版本、时间范围；且要**下推到检索阶段**，见 [企业知识库助手架构](#/deep/case-kb-agent) |
| 混合检索 | 向量 + 关键词，覆盖编号、型号、缩写，见 [检索优化](#/knowledge/retrieval-advanced) |
| 增删改与持久化 | 文档修订、下线、增量重建 |
| 批量写入与并发 | 离线摄取效率 |
| 可观测 | 检索延迟、命中分布、索引大小 |

## 三、选型对比

| 形态 | 适合 | 优点 | 代价 |
| --- | --- | --- | --- |
| 内存 / 轻量实现 | 学习、演示、小规模 | 零运维、起步快 | 重启即丢、无并发能力 |
| 关系库 + 向量扩展 | 已有数据库、数据规模中等 | 事务、权限、备份可复用 | 大规模检索性能需评估 |
| 专用向量数据库 | 大规模、高并发检索 | 索引与过滤能力完整 | 多一套基础设施 |
| 搜索引擎的向量能力 | 已有搜索集群、需要混合检索 | 关键词与向量一体 | 调优与运维成本 |

> [!TIP] 先问「要不要新引入一套存储」
> 若已有数据库支持向量类型且规模不大，复用它通常比引入专用向量库更划算。Spring AI 的 `VectorStore` 是可替换接口，正是为了这种切换，见 [记忆、RAG 与 MCP 落地](#/springai/rag-memory)。

## 四、关键参数与一致性

| 参数 | 说明 | 常见错误 |
| --- | --- | --- |
| 维度 | 必须与 embedding 模型输出一致 | 配置写错导致写入失败或检索无意义 |
| 距离度量 | 与模型、索引配置匹配 | 换了度量却没重建索引 |
| Top-K | 返回片段数 | 一味调大 → 噪声与成本上升 |
| 相似度阈值 | 低于阈值视为未命中 | 阈值过高导致本该拒答的也硬凑片段 |
| 索引参数 | HNSW 的建图 / 查询参数 | 追求极致速度导致召回下降 |
| 过滤条件 | 权限 / 版本 / 时间 | 放在检索之后 → 越权片段已进上下文 |

**一致性三条**：① 写入与查询用同一个 embedding 模型；② 换模型必须全量重建；③ 文档修订要按 `doc_id` 更新而非只追加，见 [文档解析与切分策略](#/knowledge/document-pipeline)。

## 常见坑

1. **维度不匹配**：配置与模型输出不一致，写入直接失败或结果异常。
2. **新旧模型向量混用**：相似度失去意义，答案质量骤降却难以定位。
3. **权限过滤放在检索之后**：敏感内容已进入上下文。
4. **只用向量、不用关键词**：编号、条款号、专有缩写命中差。
5. **Top-K 当作质量旋钮**：越大不等于越准，应先看命中片段质量。
6. **索引无版本 / 无重建流程**：文档更新后答案长期过期。

## 自测题

> [!QUESTION] embedding 是「压缩后的原文」吗？
> 不是。它是语义坐标，无法还原原文；索引必须同时保存 chunk 文本与元数据，才能拼进提示词并做引用展示。

> [!QUESTION] 为什么元数据过滤必须下推到检索阶段？
> 否则无权片段已经被取出并送进上下文，事后过滤无法撤回信息；权限条件应作为检索请求的一部分。

> [!QUESTION] 换 embedding 模型为什么要全量重建索引？
> 不同模型的维度与向量空间不同，新旧向量之间的相似度没有可比性；必须全量重算并保留对照评测。

> [!QUESTION] 什么时候不必引入专用向量数据库？
> 数据规模不大、已有关系库支持向量类型时，复用现有存储可省掉一整套基础设施，并复用权限、事务与备份能力。
