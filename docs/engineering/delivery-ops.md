# 交付与运维：配置、CI/CD 与灰度

> [!ABSTRACT] 一句话版本
> - Agent 的「代码」不只是代码：**提示词、工具 schema、模型档位、评测用例集**都是需要版本化与回滚的发布物。
> - 配置分三层：**静态配置**（依赖 / 结构）、**环境配置**（地址 / 超时 / 预算）、**密钥**（环境变量或密钥服务，绝不进仓库）。
> - CI 门禁顺序：格式校验 → 单测 / 集成测试 → 索引与链接自检 → 评测冒烟与安全反例 → 灰度 → 全量。
> - 灰度与回滚要能**独立切换提示词版本与模型档位**，否则出问题时只能全量回滚代码。

## 二、配置与密钥分层

| 层 | 内容 | 放哪 |
| --- | --- | --- |
| 静态配置 | 依赖版本、框架结构、工具注册清单 | 代码仓库，纳入版本管理 |
| 环境配置 | 模型地址、超时、预算上限、检索 Top-K、灰度比例 | 配置中心 / 环境变量，按环境区分 |
| **密钥** | API Key、数据库口令、MCP Token | 密钥管理服务，**绝不进仓库 / 日志 / 截图** |
| 发布物版本 | 提示词版本、工具 schema 版本、模型档位 | 可独立切换的配置项 |

> [!CAUTION] 密钥泄漏的正确处置是轮换
> 删掉提交记录并不能让密钥失效。一旦进入公开仓库，第一时间**轮换密钥**，再清理历史与加忽略规则，见 [术语速查与准备](#/start/glossary)。

**提示词也要版本化**：改动提示词会显著改变行为，必须能回答「线上跑的是哪一版」「上一版指标是多少」，见 [提示词工程](#/llm/prompt-engineering)。

## 三、CI 里跑什么

| 阶段 | 检查 | 成本 |
| --- | --- | --- |
| 静态校验 | 文档登记、H1 一致、链接、索引是否最新（本站的 `check.py`） | 极低 |
| 单测 / 集成 | 工具与编排逻辑、真实装配链路（用替身） | 低 |
| 评测冒烟 | 少量关键正例 + 全部安全反例 | 中 |
| 全量评测 | 发布前或定期，含质量与成本指标 | 较高 |
| 安全门禁 | 越权 / 未审批写操作 / 注入类指标一票否决 | — |

> [!TIP] 把「内容正确性」也纳入 CI
> 像本站这样的笔记站点，链接失效、索引过期、页面未登记都是真实故障；`tools/check.py` 在每次 push 自动跑，就是最简单有效的一道门禁。

## 四、部署与灰度

| 关注点 | 做法 |
| --- | --- |
| 依赖与运行时 | 锁定依赖（BOM / 锁文件），容器化，镜像可复现 |
| 短任务 | 同步链路，配好网关超时与线程池，见 [生产级 Agent 架构全景](#/deep/agent-architecture) |
| 长任务 | 独立 worker / 工作流引擎，状态持久化，按 run_id 查询，别用 HTTP 超时兜底 |
| 灰度维度 | 按租户 / 用户比例 / 任务类型；可单独灰度新提示词或新模型档位 |
| 观察指标 | 正确率抽检、P95 延迟、单次成本、工具失败率、拒答率、安全告警 |
| 快速回滚 | 配置开关即可回退提示词 / 模型 / 工具集，代码回滚作为最后手段 |

## 五、SLO 与值班

| 指标 | 关注 |
| --- | --- |
| 可用性 | 成功返回率、降级触发率 |
| 延迟 | P50 / P95 / P99，同步与长任务分开 |
| 成本 | 单次任务平均 token、预算熔断次数 |
| 质量 | 抽检正确率、拒答率异常波动 |
| 安全 | 越权拦截数、审批拒绝率、注入告警 |
| 可恢复性 | 长任务恢复成功率、检查点写入失败率 |

告警要能定位到 **run_id**，并附最近的发布物版本变更，否则「昨晚变差了」很难归因，见 [可观测性](#/engineering/observability)。

## 常见坑

1. **只把代码当发布物**：提示词改了却没版本、没回归、没法回滚。
2. **密钥写进配置仓库**：泄漏后需要轮换，代价极高。
3. **全量评测放进每次提交**：CI 变慢变贵，最后被绕过。
4. **长任务用 HTTP 超时兜底**：连接断了任务还在跑，状态无处可查。
5. **灰度只能整体开关**：提示词与模型无法独立回退。
6. **没有基线对照**：灰度期间无法判断「是不是变差了」。

## 自测题

> [!QUESTION] 为什么说提示词也是发布物？
> 改提示词会显著改变行为，与改代码等价；必须版本化、可灰度、可回滚，并用固定用例集对比指标。

> [!QUESTION] 配置为什么要分静态 / 环境 / 密钥三层？
> 变更频率与安全级别不同：结构与依赖随代码走，地址与预算按环境变，密钥必须放密钥服务且绝不进仓库。

> [!QUESTION] 长任务部署为什么不能用 HTTP 超时兜底？
> 连接断了任务仍可能在执行；需要独立 worker / 工作流引擎、持久化状态与按 run_id 查询，超时按任务层级单独设。

> [!QUESTION] 灰度期间至少要看哪些指标？
> 抽检正确率、P95 延迟、单次成本、工具失败率、拒答率与安全告警，并与上一版基线对比。
