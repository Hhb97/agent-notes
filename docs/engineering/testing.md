# 测试策略：从单测到评测

> [!ABSTRACT] 一句话版本
> - Agent 测试要分四层：**工具单测 → 编排单测 → 集成测试 → 评测集**，越往上越真实也越慢越贵。
> - 底层用 **mock / 固定输出替身**，让「模型」变成可预测的输入；否则测试既慢又不稳定，还会真实扣费。
> - 用例集要有三类：**正例、边界例、安全反例**；线上坏例持续回流，见 [可靠性、成本与评测门禁](#/deep/reliability-eval)。
> - 评测不是「跑一次看看」，而是**可重复、可对比、能阻断发布的门禁**。

| 层 | 测什么 | 模型怎么处理 | 运行频率 |
| --- | --- | --- | --- |
| ① 工具单测 | 工具作为普通函数的鉴权、参数、幂等、错误返回 | 不涉及 | 每次提交 |
| ② 编排单测 | 循环终止、状态更新、工具结果回填、审批中断 | 固定输出替身 | 每次提交 |
| ③ 集成测试 | 框架链路是否真的把提示词 / 工具 / 检索装好 | 替身模型 + 替身外部服务 | 每次提交 / 每日 |
| ④ 评测集 | 答案质量、工具选择、安全边界、延迟成本 | 真实模型 | 发布前 + 定期 |

## 二、让模型变可预测

| 手段 | 说明 |
| --- | --- |
| **固定输出替身** | 让「模型」按脚本返回预设文本或预设工具调用，断言业务代码如何处理 |
| **录制回放** | 录一次真实响应，之后离线重放，见 [本地开发与调试](#/engineering/local-dev-debug) |
| **故障注入** | 模拟超时、限流、工具异常，验证重试 / 降级 / 拒答路径 |
| **固定种子与参数** | 需要真实模型时固定版本与参数，但仍不保证完全一致 |

```python
# 概念示意：用替身断言「模型请求工具后，代码会执行并回填」
fake_model = ScriptedModel([
    tool_call("queryOrderStatus", {"orderId": "A-1001"}),
    final_answer("订单已发货"),
])
result = run_agent(fake_model, "A-1001 到哪了？")
assert fake_model.messages[-2]["role"] == "tool"
assert "已发货" in result
```

> [!TIP] 断言「过程」而不只是「答案」
> Agent 常见回归是「答案碰巧对了，但调错工具 / 多调了三轮」。断言工具选择、调用次数与回填消息，才能守住行为，见 [核心循环与工具调用](#/basic/loop)。

## 三、用例集设计

| 类型 | 例子 | 检查 |
| --- | --- | --- |
| 正例 | 正常问订单状态 | 答案、工具选择、依据 |
| 边界例 | 订单号格式异常、资料不足、多轮指代 | 澄清 / 拒答 / 有限重试 |
| **安全反例** | 越权查他人数据、要求删除、注入文本 | 必须拒绝且不留副作用 |
| 故障例 | 工具超时、检索为空、模型限流 | 降级路径与提示是否恰当 |
| 回归例 | 线上发现的每一个坏例 | 不再复现 |

用例集与结果要**纳入版本管理**，并保存基线指标，否则无法判断改动是提升还是回归。

## 四、CI 中的取舍

| 层 | 是否进每次 CI | 理由 |
| --- | --- | --- |
| ①② | 是 | 快、确定、不花钱 |
| ③ | 是（用替身） | 防止「配置改了链路断了」 |
| ④ 全量评测 | 发布前 / 每日 | 真实调用慢且贵 |
| ④ 冒烟子集 | 可进每次 CI | 少量关键用例 + 安全反例，快速兜底 |

安全类指标（越权调用、未审批写操作、危险语句拦截）**一票否决**，不能靠总分抵消，见 [可靠性、成本与评测门禁](#/deep/reliability-eval)。

## 常见坑

1. **所有测试都真实调模型**：慢、贵、结果不稳定，CI 变成摆设。
2. **只断言最终答案**：过程回归（选错工具、多轮循环）全漏掉。
3. **用例集只有正例**：安全边界无人验证。
4. **没有基线**：改完只说「感觉更好」。
5. **线上坏例不回流**：同类问题反复出现。
6. **替身与真实框架行为不一致**：测试通过、线上失败；集成测试要覆盖真实装配链路。

## 自测题

> [!QUESTION] 为什么 Agent 测试要分层，而不是全用真实模型跑一遍？
> 真实调用慢、贵且不确定；把工具与编排逻辑用替身做成快速确定的单测，只在顶层用真实模型验证质量，才能兼顾速度与可信度。

> [!QUESTION] 为什么断言要覆盖「过程」？
> 答案可能碰巧正确，但工具选错、多调几轮或结果没回填；这些行为回归只有断言工具选择、调用次数与消息序列才能发现。

> [!QUESTION] 安全反例为什么必须进用例集？
> 越权、危险动作、注入文本这类问题不会出现在正常用例里，只有显式反例才能验证拦截，并作为发布门禁的一票否决项。

> [!QUESTION] 全量评测为什么不放进每次 CI？
> 真实模型调用受成本、延迟与不确定性限制；通常每次 CI 跑冒烟子集 + 底层单测，全量评测放在发布前或定期运行。
