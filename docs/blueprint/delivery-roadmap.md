# 从 MVP 到生产：落地路线与验收清单

> [!ABSTRACT] 一句话版本
> - 五个阶段：**POC 验证价值 → MVP 最小闭环 → 试点灰度 → 生产化 → 规模化**；每阶段都有明确退出条件，不达标不进入下一阶段。
> - POC 阶段**只验证一件事**：模型 + 工具能不能稳定完成目标任务的闭环；不要在这个阶段搭平台。
> - 成本要按「**任务数 × 平均轮次 × 每轮 token × 冗余系数**」建模，并留失败重试与多查询扩展的余量。
> - 生产化的分水岭不是功能多少，而是**评测门禁、故障注入、灰度回滚、成本归因**四件事是否齐备。

## 二、阶段详解

| 阶段 | 目标 | 范围 | 交付物 | 退出条件 |
| --- | --- | --- | --- | --- |
| **P0 POC** | 验证闭环可行性 | 单个任务类型、1～2 个工具、无持久化 | 可打印请求的原型、10～20 条用例、结论报告 | 固定用例集上闭环成功率达标；明确「值得继续 / 不值得」 |
| **P1 MVP** | 最小可用 + 安全护栏 | 鉴权、工具幂等、预算上限、拒答、基础日志 | 同步链路、用例集（含反例）、提示词与工具 schema 版本 | 安全反例 0 例外；失败路径有确定行为 |
| **P2 试点灰度** | 真实用户验证 | 小流量 / 单租户、抽检、反馈回流 | 评测基线、灰度开关、坏例回流机制 | 质量与 CSAT 达标、成本可控、可一键回退 |
| **P3 生产化** | 稳定可运维 | 观测、评测门禁、故障注入、长任务恢复、审计 | 运行手册、SLO、告警、回滚演练记录 | 故障注入全通过；门禁阻断过一次真实回归 |
| **P4 规模化** | 多场景复用 | 多租户、模型分级路由、工具注册中心、平台化治理 | 参考架构落地、配额与成本归因、平台文档 | 容量压测通过；新增场景接入成本显著下降 |

> [!WARNING] 最常见的两种失败路线
> ① **P0 就搭平台**：价值还没验证，先引入队列、工作流引擎、多租户，最后没人用；② **跳过 P3 直接扩量**：没有评测门禁与故障演练，规模越大事故越难定位。

各阶段对应的架构工件见 [从需求到可落地架构](#/blueprint/method)，组件清单见 [通用 Agent 平台参考架构](#/blueprint/reference)。

## 三、成本模型

```text
单次任务输入 token = 稳定前缀（系统提示 + 工具 schema）
                   + 历史 + 检索片段 + 工具结果 + 用户问题
单次任务输出 token = 各轮输出之和
总 token = 任务数 × 平均轮次 × (输入 + 输出) × 冗余系数
冗余系数 ≈ 1.5 ~ 3（失败重试、查询改写、多轮循环、多智能体）

日成本 = 总 token × 单价（按模型档位分别计）
并发额度 = 峰值每分钟 token / 单个账号每分钟配额
```

| 优化杠杆 | 效果 | 代价 |
| --- | --- | --- |
| 入口路由分流简单请求 | 显著减少主模型调用 | 多一层分类逻辑 |
| 模型分级路由 | 便宜档位覆盖多数任务 | 需要失败升级与质量监测 |
| 稳定前缀 + prompt 缓存 | 降低重复输入成本 | 前缀要字节级稳定 |
| 减少轮次（工具合并 / 明确终止） | 线性降低 | 工具粒度设计要更细 |
| 裁剪工具结果与检索片段 | 降低输入 token 与噪声 | 可能丢信息，需评测 |
| 预算硬熔断 | 防账单失控 | 超限任务需明确失败路径 |

> [!TIP] 先量后优
> 用 [可观测性](#/engineering/observability) 的成本归因定位「哪个场景、哪一轮、哪个工具」在烧钱，再选杠杆。一开始就换便宜模型，往往既没省钱又降了质量。

## 四、团队分工（RACI 简表）

| 工作 | 负责 | 参与 | 知会 |
| --- | --- | --- | --- |
| 需求边界与 SLO | 产品 / 架构 | 业务方 | 全体 |
| 契约与 ADR | 架构 | 后端 / 算法 | 全体 |
| 提示词与工具 schema | 算法 / 后端 | 业务方 | 测试 |
| 状态与持久化 | 后端 | 架构 | 运维 |
| 评测用例集与门禁 | 测试 / 算法 | 业务方 | 全体 |
| 部署、观测、告警 | 运维 | 后端 | 全体 |
| 灰度与回滚决策 | 产品 + 架构 | 运维 | 全体 |

**业务方必须参与用例集标注**：只有他们能定义「什么算答对」「什么算绝对不能做」，见 [评测系统深入](#/internals/eval-system)。

## 五、风险清单

| 风险 | 信号 | 缓解 |
| --- | --- | --- |
| 价值不成立 | POC 用例集成功率长期不达标 | 明确止损，缩场景或停止 |
| 提示注入 / 越权 | 安全反例出现例外 | 工具层白名单 + 审批，一票否决 |
| 成本失控 | 单次成本异常上涨 | 预算硬熔断 + 成本归因 + 轮次告警 |
| 框架版本漂移 | 升级后行为变化 | 依赖锁定 + 升级重跑全量评测 |
| 长任务不可恢复 | 崩溃后重跑或卡死 | 事件日志 + 检查点 + 故障注入演练 |
| 提示词 / 工具 schema 变更失控 | 指标无归因地波动 | 版本化 + 灰度 + 基线对比 |
| 供应商锁定 | 换模型代价高 | 模型网关抽象 + 保留留出集 |
| 组织性风险 | 无人维护用例集 | 明确 owner，坏例回流纳入流程 |

## 六、总验收清单

**契约与设计**
- [ ] 需求四象限结论、非功能指标、ADR 齐全并评审
- [ ] API / 事件 / 工具 schema / RunState 契约版本化

**正确性**
- [ ] 固定用例集（正例 / 边界 / 安全反例 / 故障例）自动可跑
- [ ] 留出集单独验证泛化；基线可对比，逐例结果可 diff

**安全**
- [ ] 越权调用、未审批写操作、危险语句拦截率 100%
- [ ] 外部内容按不可信数据处理；密钥不进仓库与日志

**可靠性**
- [ ] 故障注入：模型超时、工具失败、进程重启、审批拒绝 / 超时、队列积压
- [ ] 长任务恢复成功率达标，取消不产生新副作用

**成本与性能**
- [ ] 预算、轮次、并发硬上限生效；成本可归因
- [ ] P50 / P95 延迟、单次成本符合 SLO

**交付**
- [ ] 观测与告警接好，run_id 贯通全链路
- [ ] 灰度开关、快速回滚、运行手册、值班响应就绪

## 深入追问

> [!QUESTION] POC 阶段为什么不该搭平台？
> 此时连「模型 + 工具能否稳定完成目标闭环」都未验证，引入队列、多租户与工作流引擎只会放大沉没成本；先用 10～20 条用例给出「继续 / 止损」结论。

> [!QUESTION] 生产化的分水岭是什么？
> 不是功能数量，而是评测门禁、故障注入、灰度回滚、成本归因四件事齐备；缺任一项，规模放大后事故都难以定位与止损。

> [!QUESTION] 成本模型里冗余系数覆盖什么？
> 失败重试、查询改写、多轮循环与多智能体委派，通常使实际 token 达到理论值的 1.5～3 倍；不计入会在峰值击穿配额或预算。

> [!QUESTION] 为什么业务方必须参与评测用例集？
> 只有业务方能定义「什么算答对」以及「什么绝对不能做」；缺了这层标注，正确率与安全反例都无法成立，门禁也就失去意义。
