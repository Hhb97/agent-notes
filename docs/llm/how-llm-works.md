# 大模型怎么工作：token、预测与幻觉

> [!ABSTRACT] 一句话版本
> - 大模型的核心动作只有一个：**根据已有文本，预测下一个最可能的 token**，然后把自己输出的 token 接回去继续预测。
> - **token 是计量单位**（计费与长度都按它算），**上下文窗口是单次请求能装下的 token 上限**，超出就装不进去。
> - **幻觉**不是「模型坏了」，而是它在没有依据时仍然必须给出一个看起来合理的续写；解决方式是给依据（RAG）与约束（拒答、校验），不是换个框架。
> - 模型**没有实时数据、没有跨请求记忆、不执行代码**——这三条边界正是 Agent 要补的东西。

## 一、从「预测下一个词」说起

把模型想象成一个极其熟练的「续写器」：给它一段文本，它输出下一个 token；把输出接回原文，再预测下一个，如此反复，直到生成结束标记或达到长度上限。

这个视角能解释很多现象：

- **为什么回答会跑偏**：前面的 token 一旦选错，后面都在错误上下文上续写。
- **为什么提示词顺序有影响**：模型只能看到「之前的」内容，越靠后的指令越靠近生成位置。
- **为什么输出有随机性**：每一步是在候选 token 上按概率采样，参数控制采样的「保守程度」，见 [模型选型与关键参数](#/llm/model-selection)。

## 二、token 与上下文窗口

| 概念 | 是什么 | 对开发的直接影响 |
| --- | --- | --- |
| **token** | 文本被切成的模型处理单元，可能是一个词、词的一部分、一个汉字或标点 | 计费、长度限制、切分都按 token 计，中文通常比英文更耗 |
| **上下文窗口** | 单次请求能容纳的 token 总量（输入 + 输出预留） | 系统提示、历史、检索片段、工具结果都在抢份额，见 [上下文工程深入](#/deep/context-engineering) |
| **输出上限** | 单次最多生成多少 token | 未预留额度会被截断，长输出要显式配置 |

> [!NOTE] 训练与推理的区别（了解即可）
> 预训练阶段模型从海量文本里学「下一个词最可能是什么」；后续对齐训练让它更会遵循指令、更符合人类偏好。**推理时参数不变**——所以 RAG 只是把资料临时拼进输入，并没有「教会」模型什么，见 [上下文、记忆与 RAG](#/basic/context-rag)。

## 三、幻觉从哪来

模型被要求「无论如何在给定上下文后继续输出」。当上下文里没有依据、或依据互相矛盾时，它仍会给出一个**语言上最流畅**的续写——这就是幻觉。

| 类型 | 例子 | 主要对策 |
| --- | --- | --- |
| 事实性幻觉 | 编造不存在的订单号、政策条款 | 给依据（检索 / 工具查询）+ 要求注明出处 |
| 依据性幻觉 | 资料里没有却说「根据文档…」 | 提示词明确「资料不足时说明不知道」+ 拒答用例，见 [提示词工程](#/llm/prompt-engineering) |
| 过程性幻觉 | 声称已调用工具、已发送邮件 | 工具结果必须由代码回填，不能让模型自述执行结果，见 [核心循环与工具调用](#/basic/loop) |
| 引用性幻觉 | 编造不存在的片段 ID | 生成后按 ID 回查，见 [企业知识库助手架构](#/deep/case-kb-agent) |

> [!TIP] 一个实用的心智模型
> 把模型看成「**很有文采但没有权限、没有记忆、没有联网的实习生**」：给它资料它能总结，不给资料它也会努力编。工程上要做的就是**给依据、设边界、验结果**。

## 四、三条能力边界 → 三条 Agent 设计

| 模型做不到 | 于是 Agent 需要 |
| --- | --- |
| 获取训练数据之外的实时信息 | **工具**（查接口）与 **RAG**（查文档） |
| 记住上一次请求说过什么 | **状态 / 记忆**（每次把历史重新发一遍） |
| 执行任何动作 | **工具执行层**（代码真正执行，并做鉴权） |

这三条正好对应 [Agent 是什么](#/basic/what-is-agent) 里的四要素，也解释了为什么"换个更贵的模型"解决不了工具设计问题。

## 常见坑

1. **以为「多轮对话」是模型自带记忆**：其实是程序每次重发历史。
2. **以为长上下文模型就不需要检索**：窗口变大但噪声与成本也变大，关键信息仍可能被稀释。
3. **靠提示词一句「不要编造」治幻觉**：需要给依据、可拒答、可校验，并用用例集验证。
4. **忽略中文 token 消耗**：按字符数估算预算会明显偏低。
5. **把模型自述当执行证据**：是否执行只看工具层日志。

## 自测题

> [!QUESTION] 用一句话说明大模型在做什么？
> 根据已有 token 序列预测下一个最可能的 token，并不断把输出接回输入，自回归地生成完整回答。

> [!QUESTION] 为什么会出现幻觉？
> 模型总要在给定上下文后续写，当上下文缺乏依据时，它仍会输出语言上最流畅的内容；这是生成机制的自然结果，不是故障。

> [!QUESTION] 上下文窗口与「记忆」有什么区别？
> 窗口是单次请求的容量上限；记忆是程序为跨轮次保留什么做的工程决策，实现方式是每次请求重新带上历史。

> [!QUESTION] 模型不能执行代码，为什么 Agent 却能查数据库？
> 模型只输出工具调用请求，由你的代码执行真实查询并把结果回填进上下文，见 [核心循环与工具调用](#/basic/loop)。
