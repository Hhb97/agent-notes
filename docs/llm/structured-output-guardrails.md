# 结构化输出与护栏

> [!ABSTRACT] 一句话版本
> - 结构化输出有四个层级：**提示词约定 → schema 约束 → 类型映射 → 业务校验**，越往后越可靠。
> - **护栏分三层**：输入护栏（拦住不该进来的）、输出护栏（校验该出去的）、工具护栏（决定能不能执行）——最后一层才是权限边界。
> - 必须设计**拒答与兜底**：资料不足、校验失败、超预算时都要有确定行为，而不是硬给一个答案。
> - 校验失败可以有限重试，但**只重试可修正错误**，且计入预算与审计。

## 一、四级约束

| 级别 | 做法 | 可靠性 | 典型失败 |
| --- | --- | --- | --- |
| ① 提示词约定 | 「请返回 JSON，字段为…」 | 低 | 多一句客套话就解析失败 |
| ② schema 约束 | 请求里带 JSON schema / 响应格式要求 | 中高 | 字段缺失、类型漂移 |
| ③ 类型映射 | 框架把输出转成 Java 对象 / Pydantic 模型 | 高 | 复杂嵌套容易漏字段 |
| ④ 业务校验 | 检查值域、引用是否存在、是否与工具结果一致 | 最高 | — 这是最后一道 |

```text
模型文本 → 解析 → schema 校验 → 映射为对象 → 业务规则校验
                     ↓ 失败                    ↓ 失败
              有限重试（1～2 次）        拒答 / 降级 / 转人工
```

Spring AI 侧对应 `.entity(...)`，Python 侧对应 `output_type` + Pydantic，见 [工具调用与结构化输出](#/springai/tools) 与 [结构化输出、检索与评测](#/python/output-rag-eval)。

## 二、三类护栏

| 类型 | 拦什么 | 例子 | 局限 |
| --- | --- | --- | --- |
| **输入护栏** | 不该进入模型的请求 | 越权请求、超长输入、敏感信息、明显注入文本 | 不能替代权限判断 |
| **输出护栏** | 不该返回给用户的内容 | schema 校验、引用真实性、敏感字段脱敏、格式约束 | 校验格式不保证事实正确 |
| **工具护栏** | 不该被执行的动作 | 参数白名单、当前会话鉴权、写操作审批、幂等 | **唯一真正的权限边界** |

> [!CAUTION] 护栏叠加不等于安全
> 输入 / 输出护栏是降低误触发与减少泄漏的**辅助层**；模型仍可能绕过它们发出工具调用请求。是否执行必须由工具执行层基于当前登录身份决定，见 [评测、可观测与安全边界](#/basic/eval-safety)。

## 三、拒答与兜底

| 场景 | 期望行为 |
| --- | --- |
| 检索片段不足 / 不相关 | 「暂无可靠资料」并说明缺什么，不推测 |
| 工具不可用 | 明确告知暂无法查询，而不是编一个结果 |
| 输出校验反复失败 | 降级为「无法生成结构化结果」或转人工 |
| 超预算 / 超轮次 | 明确返回「未完成」，附已完成步骤 |
| 请求越权 | 直接拒绝并留审计告警 |

拒答要**写进系统提示 + 写进评测用例集**，否则改一次提示词就可能悄悄失效，见 [提示词工程](#/llm/prompt-engineering)。

## 四、失败重试策略

| 失败 | 是否重试 | 说明 |
| --- | --- | --- |
| 多输出了说明文字 | 是（1～2 次） | 把解析错误精简后回填，要求严格按 schema 输出 |
| 字段类型不符 | 是（有限次） | 明确给出期望类型 |
| 引用 ID 不存在 | 否 | 属于事实错误，应去掉引用或拒答 |
| 权限 / 安全校验失败 | **否** | 立即结束并告警 |
| 连续失败达到上限 | 否 | 转人工或降级，计入成本与审计 |

> [!TIP] 输出类型设计要克制
> 字段少、含义明确、避免深层嵌套与大量可选字段；复杂结果拆成多次调用。**类型校验保证格式，不保证事实**，业务校验不能省。

## 常见坑

1. **手工 `json.loads` 模型输出**：格式漂移就崩，应升级到 schema + 类型映射。
2. **把所有失败都重试**：安全类失败被反复触发，还放大成本。
3. **没有拒答分支**：模型在没依据时只能编。
4. **把 guardrail 当鉴权**：提示词与输出校验都可被绕过。
5. **校验失败静默吞掉**：下游拿到残缺对象却无人知晓。
6. **输出类型过于复杂**：字段缺失率反而上升。

## 自测题

> [!QUESTION] 结构化输出的四级约束是什么？
> 提示词约定、schema 约束、类型映射、业务规则校验；可靠性依次提高，业务校验是最后一道。

> [!QUESTION] 为什么工具护栏才是真正的权限边界？
> 输入与输出护栏只影响进出模型的文本，模型仍可能发出工具调用请求；是否执行必须由工具层基于当前会话身份判断。

> [!QUESTION] 哪些输出失败适合有限重试？
> 可修正的格式类失败（多余说明文字、字段类型不符）；引用不存在、权限校验失败、连续失败达到上限都不应重试。

> [!QUESTION] 为什么拒答要同时写进提示词和评测集？
> 提示词提供退出路径，评测集防止后续改动把这条规则改没；两者缺一，模型在资料不足时容易重新变成「硬答」。
